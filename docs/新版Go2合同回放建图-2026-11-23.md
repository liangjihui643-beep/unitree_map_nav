# 新版 Go2 合同回放建图与候选规则首轮（2026-11-23）

依据《新版 Go2 接口与感知建图实施计划-2026-11-23》第 2 步：接合同回放建图入口，并在同一观测/同一外部位姿上比较旧规则与候选规则。**未切换默认地图**；结果只作首轮模块对照。

## 1. 前置修正（第 1 步复核问题）

- `sensor_meta[3]` 改为**高度筛选与归约前的有效原始射线数 / 648**；72 方位有效比单独作为诊断字段；
- 六步冒烟复跑：`sensor_meta[3]` 前五步 0.6852、第六步 0.6836；72 方位比 1.0 / 0.9861；原始/方位两个比例分开记录；
- `PublicTask.load` 改为失败即停：manifest 清单缺失、文件摘要不符、catalog 条目缺失或 manifest SHA 不符都直接抛错；
- 单元测试含 `324/648 = 0.5` 的 sensor_meta 断言。

## 2. 合同短记录

`scripts/contract_capture.py` 沿公开 manifest 的 14 个 route 点（初始位姿起）按 0.15 m 采样，共 **154 帧**：

- 位姿来自公开 route（脚本位姿，外部估计；不是估计器输出）；
- 输入张量只含 LiDAR 合同 obs（72 距离 + 72 掩码）、IMU 四元数；无仿真真值；
- `truth_pose` 单独保存用于评分；两套地图使用**完全相同**的观测、位姿、四元数；
- 覆盖连续坡、普通墙、带顶入口/隧道段、相邻平地（route 依次经过 ramp、平台、隧道区）；
- 产物：`output/contract-capture-01/frames.npz`、`frames.jsonl`、`capture.json`。

## 3. 两套规则

`src/go2_rescue/contract_map.py`：

### 旧规则 `LegacyMap`

- 每个有效方位按固定中心俯仰 0° 重建一个端点；
- 用 `pose.z - base_height` 作为地面估计；相对高度 <0.10 m 记自由/地面，0.10–0.55 m 记占据，>0.55 m 记上方结构；
- 对应“每方位最近回波 + 固定高度假设”的旧式规则。

### 候选规则 `ContractMap`

- 每方位枚举 9 个合同俯仰，作为**同一回波的互斥解释**，不累计 9 次占据；
- 安装点取任务配置 `[0.32,0,0.05]`，经 IMU 四元数旋转；
- 地面未知时端点只记 `seen/undetermined`，不直接写永久障碍；
- 地面由最低候选回波多帧投票建立（≥2 帧），地面已知后才把候选分为地面/机身高度障碍/上方结构；
- 同一方位的一条回波只允许一个互斥解释：只有所有候选落在同一格且类别一致时才提交一次证据；跨多格或类别混合时**整条回波入待定队列**，不得给多个格各记一次；
- 待定回波保存候选端点与位姿，地面建立后由 `_recompute_pending()` 重新分类并提交一次；仍不明确则继续待定。

## 4. 同观测 A/B 结果（地面补全 + 独立墙段）

`output/contract-map-compare-01/comparison.json`，154 帧、固定局部区域 17374 格；旧规则为固定俯仰 0° 的简化实现。

| 指标 | 旧规则 | 候选规则 |
|---|---:|---:|
| 占据/墙段格 | 2153 | 756（19 个墙段） |
| 坡面假占据 | 372 | 144 |
| 平地假占据 | 266 | 104 |
| 机身高度内真障碍确认 | 756/893 | **357/893** |
| 错误自由 | 0 | 0 |
| 自由格 | 0 | 2 |
| 可信地面格 | — | 461（近身种子 7） |
| 待定 / 待定比例 | — | 7034 / 1.00 |
| 发布冲突 | — | 0 |
| 待定覆盖 top-down 诊断 | — | 10090/11438（不是确认占据） |

- **地面局部补全**：从近身低候选种子沿邻近低候选有界扩展，遇高差 >0.12 m 或缺测断口停止；在线逐帧补全后可信地面达到 461 格。字段已从“本体支撑”改为 `near_body_seed`。
- **墙体独立确认**：不再用候选高度跨度作为墙判据；以代表候选做多视点聚类，视点按 0.25 m 分箱、至少两个不同视点才计数；沿拟合线只栅格化有支持的长度，缺口分段。每束只投一票（墙票 289），共 19 个墙段、756 格；同一格多视点支持另作补充墙格。
- **发布互斥**：`published_free` 排除 wall/occupied/overhead，`published_occupied` 包含墙段；`free_occupied_conflicts=0`。
- 结果：真墙确认从 0/893 恢复到 357/893；坡面/平地假占据 144/104，仍低于旧规则 372/266；错误自由仍为 0。
- 屋顶与地面可在同一平面位置：墙段栅格化时，若墙段最低高度高于当地地面 + `body_clearance`，记入上方结构而不是墙；只有净空不足才阻断通行。
- 对照图：`output/contract-map-compare-01/comparison.png`（左旧规则、右候选：地面绿、墙段黑、待定橙、上方结构蓝）。

### 连续更新入口

`ContractMap.update()` 现在每帧执行地面局部补全与待定重算，每 10 帧重置并重新确认墙段；`finalize()` 是幂等的收尾。`online_timeline.json` 每 10 帧记录一次可用图层：

- 首个墙段出现在第 **10** 帧，首个可信地面在第 **40** 帧；
- 第 150 帧时 ground 460、wall 756、occupied 756、free 2、pending 6992；
- 16 个时间点说明图层不是只在回放结束后才有输出。

这是 154 帧连续更新联调，不是仿真整场；参数、位姿仍是同一脚本记录。

## 5. 判定

- 本轮是**同一 154 帧、同一脚本位姿的模块对照**；位姿来自公开 route 插值，不是估计器输出；`truth_pose` 只用于评分；
- 旧规则是“固定俯仰 0°”的简化基线，不是项目原完整旧地图；
- 真墙确认恢复到 357/893，坡面假占据 144（低于本轮目标 161）；但待定比例仍为 1.0、自由仅 2 格，**不能升级为默认地图**；
- 未使用 RGB；没有入口特判；隧道与地面/墙使用同一规则；
- `seen` 把所有候选落点都标为见过，因此 7034 不能和旧版 2153 个占据格直接比较未知区扩张。

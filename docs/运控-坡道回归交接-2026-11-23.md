同一工作树在 20.04 和 24.04 都复现；这不是 Ubuntu 24.04 环境迁移造成的。

## 已发现的配置差异

- 测试直接创建 `ConvexMPC`，其 `terrain_slope_limit_deg` 默认值为 **15°**（`src/go2_rescue/mpc_locomotion.py:203`）。
- 正式仿真循环每个控制周期设置：

```python
controller.terrain_slope_limit_deg = max(
    15., float(config.slope_limit(last_step.pose.xy())))
```

（`src/go2_rescue/mujoco_sim.py:627`）

- MPC 只有在 `terrain_slope_limit_deg > 15.` 时才切换到坡道步态/坡面处理（`src/go2_rescue/mpc_locomotion.py:426` 附近）。
- 因此测试与正式坡道仿真可能走了不同控制路径；这不等于已经找到失败根因。

## 探索性对照（未改仓库测试）

用 `configs/perception-coverage-tour.json` 的 `terrain_slope_regions` 做了一次临时对照：

- 起点世界坐标 `(1.1, 4.0)`；
- 按 map 坐标 `qpos[:2] - [.8, .8]` 计算区域，坡道区域命中 `max_slope_deg=20`；
- 每控制周期设置 `terrain_slope_limit_deg=max(15, 20)=20`；
- 结果：`qpos[1]=4.779`，仍小于 4.88；`terrain_updates=0`。

这说明“只把上限改成 20”仍不能通过，且 `terrain_updates=0` 说明坡道地形观测没有按预期更新，需运控侧继续查：

1. 正式坡道运行时实际加载的配置/区域坐标；
2. `observe_terrain()` 为什么没有产生 `terrain_updates`；
3. `terrain_plane` 的坡度和高度随位置的曲线；
4. 坡中段触地高度/姿态跟踪与 MPC 参考的偏差。
